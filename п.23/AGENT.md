# AGENT.md — Конвейер анализа судебной практики по п. 23 Пленума ВС РФ № 15 от 29.05.2018

**Назначение файла:** пошаговая инструкция для любой сессии Claude Code, чтобы воспроизвести анализ, уже выполненный для 1кас и 2кас, на остальных кассационных судах (3кас–9кас, СОЮ) с идентичным результатом. Запуск: пользователь пишет «п23: Nкас» или «выполни п.23/AGENT.md для Nкас».

---

## 0. Контекст задачи

- Источник практики: файлы `п.23/<суд>/<суд>.txt` (для 7кас и 8кас — две части: `<суд>_ч.1.txt`, `<суд>_ч.2.txt`).
- Каждый файл — выгрузка определений кассационного суда по делам о взыскании зарплаты при неоформленных трудовых отношениях.
- Предмет анализа — **только применение п. 23 Постановления Пленума ВС РФ от 29.05.2018 № 15**: при отсутствии письменных доказательств размера зарплаты суд вправе определить её исходя из обычного вознаграждения работника его квалификации в данной местности, при невозможности — из МЗП в субъекте РФ (ст. 133.1 ТК).
- Текущий статус всех судов — в [СТАТУС.md](СТАТУС.md). **Обновляй его после каждого суда.**

## 1. Конвейер (5 шагов)

### Шаг 1. Разметка

1. Проверь наличие и размер файлов: `ls -la "п.23/<суд>/"`. Если папка пуста — сообщи пользователю и стоп.
2. Найди границы определений (Grep, output_mode content, -n):
   паттерн `КАССАЦИОННЫЙ СУД ОБЩЕЙ ЮРИСДИКЦИИ` (для СОЮ — сначала посмотри заголовок первых строк файла и адаптируй паттерн).
3. Для многочастных файлов (7кас, 8кас): обработай каждую часть отдельно, нумерация дел сквозная (ч.2 продолжает ч.1). Проверь, не дублируется ли последнее дело ч.1 в начале ч.2.
4. Разбей дела на группы по 10 (последняя — остаток). Определи строковые диапазоны: от строки начала первого дела группы до строки перед началом первого дела следующей группы.

### Шаг 2. Параллельные агенты-аналитики (по одному на группу)

Запусти всех агентов одним блоком (background). **Промпт-шаблон** (подставь СУД, ФАЙЛ, СТРОКИ, ГРУППА):

```
Ты — юрист-аналитик. Прочитай файл "<путь>" в диапазоне строк <A>–<B> (Read с offset/limit,
несколько вызовов). ВНИМАНИЕ: Read обрезает строки длиннее ~2000 символов — дочитывай через
Bash: sed -n 'NNp' "<путь>".

Диапазон содержит <K> определений <название суда> (каждое начинается со строки "<ЗАГОЛОВОК>").
Дела — о взыскании зарплаты / установлении факта трудовых отношений при неоформленных отношениях.

Контекст — п. 23 Постановления Пленума ВС РФ от 29.05.2018 N 15: при отсутствии письменных
доказательств размера зарплаты работника у работодателя-физлица (ИП/не ИП) или микропредприятия
суд ВПРАВЕ определить её из обычного вознаграждения работника его квалификации в данной местности,
при невозможности — из МЗП в субъекте РФ (ст. 133.1 ТК).

ЗАДАЧА 1 — ЗАПИШИ файл "п.23/<суд>/дела_<диапазон>.md" (инструмент Write) со структурой:
# <Название суда> — анализ определений, дела <диапазон>
**Источник:** <файл>, строки A–B
Для КАЖДОГО определения:
### Дело N <номер дела> (определение от <дата> N <номер>)
1. **Фабула** (1–2 предложения: истец/должность, ответчик — физлицо/ИП/организация,
   обсуждался ли статус СМП/микропредприятия, как оформлялись отношения, заявленные суммы).
2. **Применение п. 23**: цитирует ли (да/нет + короткая цитата).
3. **Как определён размер зарплаты**: (а) обычное вознаграждение — ЧЕМ подтверждено;
   (б) МЗП/МРОТ; (в) иной способ. Конкретные суммы.
4. **Бремя доказывания и оценка доказательств**.
5. **Итог** (оставлено/отменено, в какой части).
6. **Ключевой вывод по п. 23** (1–2 предложения).
В конце файла — "## Общие наблюдения по группе": 4–6 пунктов.

ЗАДАЧА 2 — ВЕРНИ в финальном сообщении (это отчёт оркестратору, не файл):
А) Таблицу-строки по каждому делу, КАЖДАЯ СТРОКА строго в формате:
N | определение, дата | стороны (должность → работодатель) | способ определения размера (≤8 слов) | итог (≤5 слов) | ключевой вывод (≤15 слов)
Б) Общие наблюдения по группе (те же 4–6 пунктов, сжато до 60 слов каждый).
Не дублируй полный текст дел в ответ — он уже в файле.
```

### Шаг 3. Сбор и контроль

- Дождись всех агентов. Проверь `ls -la п.23/<суд>/` — все групповые файлы созданы, размеры адекватны (25–50 КБ).
- Если отчёт агента оборвался — продолжи того же агента через SendMessage (дозапрос недостающего), НЕ запускай нового.
- Отметь дубликаты дел в файле-источнике (были в 2кас, дело 43) — в таблицу и нумерацию включай с пометкой.

### Шаг 4. Итоговые выводы (пишет оркестратор)

Создай `п.23/<суд>/итоговые_выводы.md`:
1. Шапка: источник, число определений/уникальных дел, связанные и повторные дела, ссылки на групповые файлы и таблицы.
2. Раздел «I. Выводы по каждому делу» — по 2–4 строки на дело (из таблиц-строк агентов): номер определения, стороны, способ определения размера, итог, ключевой вывод курсивом.
3. Раздел «II. Общие выводы по практике <суда>» — 8–11 пунктов по стандартным рубрикам (см. раздел 2 ниже).
4. Раздел «III. Сравнение с уже обработанными судами» — 3–6 пунктов: совпадения/расхождения с 1кас, 2кас и другими готовыми (читай их итоговые_выводы.md).

### Шаг 5. Таблицы

1. `п.23/<суд>/сводная_таблица.csv` — первая строка BOM (﻿), разделитель «;», все поля в двойных кавычках. Колонки: №; Определение; Дата; Дело N; Истец (должность); Ответчик; Способ определения размера ЗП; Размер / база расчёта; Итог; Ключевой вывод по п. 23.
2. `п.23/<суд>/сводная_таблица.md` — те же строки в markdown-таблице (6 колонок: № | Определение, дата | Стороны | Способ | Итог | Ключевой вывод).
3. Обнови `п.23/СТАТУС.md` (статус суда → ✅, дата, число дел, ссылки).

## 2. Стандартные рубрики анализа (калибровка по 1кас/2кас)

Общие выводы по каждому суду формулируй по этим рубрикам — они обеспечивают сопоставимость между судами:
1. **Сфера п. 23**: применяется ли формула «актуальны для всех субъектов трудовых отношений»; проверяется ли статус СМП/микропредприятия; дела, где статус стал значимым.
2. **Иерархия способов**: письменные доказательства → обычное вознаграждение → МЗП. Что признаётся письменными доказательствами (договор, штатное расписание, 2-НДФЛ/ИЛС, переписка, приглашение о работе, записи работника).
3. **Обычное вознаграждение**: источники (Росстат по профгруппе/ОКВЭД, вакансии, зарплата коллег, рыночные сведения); требования к сопоставимости статистики (квалификация, регион, год, сегмент СМП).
4. **МРОТ/МЗП**: условия перехода; отмены за механический МРОТ; география (место работы vs юрадрес работодателя).
5. **Бремя доказывания**: на работодателе/работнике; следствия молчания сторон; «односторонние» документы работодателя.
6. **Свидетели и вакансии**: допустимость для размера зарплаты (у судов расходится: 1кас отвергает вакансии, 2кас допускает; 2кас делит свидетелей на «о фактических выплатах» — допустимы и «о согласованном размере» — недопустимы по ст. 60 ГПК).
7. **Техника взыскания**: прямой расчёт из статистики vs «заявленное + контроль соразмерности»; статистика как потолок; работает ли п. 23 в пользу работодателя.
8. **Связки с другими нормами**: ст. 236 ТК (неначисленная зарплата), ст. 139 ТК/Положение 922 (средний заработок за прогул), ст. 184, 279 ТК, ФЗ-125, преюдиция.
9. **Типовые ошибки нижестоящих судов → основания отмен** (перечислить с номерами дел).
10. **Статистика исходов**: сколько оставлено/отменено, доля отмен по существу п. 23.

## 3. Технические правила (грабли, встреченные в 1кас/2кас)

- **Read обрезает строки >2000 символов** → агенты дочитывают через `sed -n 'NNp'` в Bash.
- **Ответ агента может обрезаться в уведомлении** → поэтому полный анализ агент ПИШЕТ В ФАЙЛ сам (ЗАДАЧА 1), а возвращает только компактные строки (ЗАДАЧА 2). Никогда не переписывай отчёты агентов в файлы вручную.
- **Кириллические пути** — в Bash заключай в кавычки; в именах файлов может быть неразрывный пробел (проверяй `ls -b`).
- **Дубликаты дел** в источнике — помечай, нумерацию не сдвигай (дело 43 в 2кас = дубль 42).
- **Обезличенные тексты**: номера определений/дел могут отсутствовать («ДД.ММ.ГГГГ», «ФИО1») — фиксируй как «обезличено», не выдумывай.
- **Многочастные файлы** (7кас, 8кас) — сквозная нумерация, проверка стыка на дубль.

## 4. Финал проекта (после последнего суда)

Создай `п.23/сравнение_всех_кас.md`:
1. Сводная матрица: строки — рубрики из раздел 2, столбцы — суды (1кас…9кас, СОЮ).
2. Рейтинг судов по «про-работническости» техники (прямой расчёт из статистики vs фильтр).
3. Расхождения, требующие унификации (кандидаты на обзор ВС РФ).
4. Библиотека «эталонных» определений по каждой рубрике со ссылками на файлы групп.

## 5. Почему схема такая (уроки 1кас/2кас)

- В 1кас/2кас агенты возвращали полные отчёты текстом (~75 тыс. токенов), а оркестратор вручную переписывал их в 9 файлов (~60 тыс. токенов вывода) — двойная работа и риск обрыва отчёта (случилось в 2кас, группа 21–30). **Теперь агенты пишут файлы сами**, оркестратор — только итог и таблицы.
- Группы по 10 дел (~500–700 строк) оптимальны: агент читает диапазон за 4–6 вызовов Read, укладывается в лимиты.
- Запуск всех агентов одним блоком в background: 5–6 групп параллельно ≈ 10 минут на суд.
